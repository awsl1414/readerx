# ReaderX Web Design Philosophy

> 本文档是 ReaderX Web 前端的中心设计方针。所有 UI 决策、组件选型、交互行为必须以此为参照，而非逐页设计稿。

## 1. 产品定义

ReaderX 不是一个「电子书管理器」。它是一个**个人阅读空间**。

管理是手段，阅读是目的。每一次设计决策都必须回答：**这有没有降低用户进入阅读状态的门槛？**

### 产品人格

ReaderX 的气质：

| 关键词 | 含义 | 反面 |
|---|---|---|
| **安静** | UI 存在感极低，内容始终是主角 | 花哨动效、装饰性元素 |
| **流畅** | 状态切换是连续的空间变化，不是页面跳转 | 白屏闪烁、硬切、loading 转圈 |
| **精密** | 排版、间距、对齐严格遵循系统，没有"差不多" | 随意 padding、不一致圆角 |
| **智能** | 系统主动帮助用户恢复上下文，用户不需要找功能 | 被动等待用户操作的功能面板 |

参考气质对标：Apple Books（安静沉浸）+ Linear（精密流畅）+ Arc（空间连续）。

不要对标：后台管理系统、Tailwind UI demo、传统 Electron 工具。

## 2. 空间模型：状态空间，不是页面栈

### 核心原则

用户不应该有「我进入了另一个页面」的感觉。所有交互是**同一个空间内的状态变化**。

```
传统 Web（禁止）:
  /library → click → /book/123 → click → /reader/123
  每次跳转 = 上下文丢失 = 白屏 = 打断心流

ReaderX（目标）:
  空间 A（书架）
    → 书卡展开为详情层（overlay）
      → 详情层 morph 为阅读层（spatial transition）
        → 阅读层全屏沉浸
        ← Esc / 返回手势 ← 层层回退
```

### 层级架构

ReaderX 由以下层级叠加组成，每层都是前一层的增量：

| 层级 | 内容 | 交互 |
|---|---|---|
| **Layer 0: 基底** | 侧边栏 + 主内容区 | 始终存在（阅读沉浸时隐藏） |
| **Layer 1: 详情** | 书籍详情 Sheet/Modal | 从书卡 morph 展开 |
| **Layer 2: 阅读** | 阅读器全屏内容 | 从详情层连续过渡进入 |
| **Layer 3: 控制** | 设置面板、TOC、搜索 | 只在交互时浮出，几秒后自动消失 |
| **Layer 4: 命令** | ⌘K 命令面板 | 全局随时唤起，覆盖一切 |

关键：每一层保留上一层的上下文。返回不是「重新加载上一页」，而是「收起当前层」。

### 导航不是路由跳转

| 传统做法 | ReaderX 做法 |
|---|---|
| `<Link href="/reader/123">` | 触发 reading state，进入 Layer 2 |
| 浏览器后退按钮 | 收起当前层，恢复上层状态 |
| `router.push()` | 空间状态变更 + shared element transition |
| `getServerSideProps` | 数据预取在状态切换前完成 |

技术实现：View Transitions API + Next.js App Router parallel routes + CSS `@starting-style`。

## 3. 信息密度：不均匀分布

人类注意力天然不均匀。UI 也必须不均匀。

### 视觉权重阶梯

首页是最佳示例。每一区块有明确不同的视觉权重：

```
视觉权重 5（最强）—— 继续阅读 Hero
  占据最大面积，封面 + 标题 + 进度条 + 一键进入
  这是首页存在的核心意义：恢复阅读上下文

视觉权重 3 —— 最近在读横向滚动流
  小封面卡，横向滚动，快速切换
  功能：快速切换最近的书

视觉权重 2 —— 收藏分组 Chips
  单行，可交互，视觉退让
  功能：过滤和分类

视觉权重 1（最弱）—— 书库预览
  更小的封面，更低的对比度
  功能：引导去书库完整页

视觉权重 0 —— 书源状态指示
  一行文字，最弱的视觉存在
  功能：系统健康确认，不需要操作
```

### 信息权重规则

- **面积 = 重要性**。最重要的内容占据最大空间。
- **滚动 = 降低优先级**。需要滚动才能看到的内容权重更低。
- **对比度 = 注意力**。高对比度元素吸引视线，低对比度元素退让。
- **交互密度与视觉权重匹配**。高权重区域可交互，低权重区域只读。

### 禁止的模式

- 所有卡片等大的网格（NAS 文件管理器）
- 所有文字等大的列表（后台表格）
- 每个区域有相同 padding 的布局
- 无主次之分的 dashboard

## 4. 交互哲学：沉浸优先

ReaderX 的统一操作原则是 **Immersive-first**。

### 操作层级

| 层级 | 触发方式 | 示例 |
|---|---|---|
| **零操作** | 系统主动呈现 | 继续阅读 Hero、书源状态提示 |
| **单操作** | 一次点击/轻触 | 点击封面进入阅读、切换 Tab |
| **上下文操作** | 在当前内容上操作 | 选中文字 → 浮出气泡、hover → 显示操作 |
| **命令操作** | ⌘K / 搜索 | 高级操作、书源管理、设置 |
| **深层操作** | 侧边栏/菜单 | 书源编辑、导入、分组管理 |

规则：**80% 的用户操作应该在「单操作」层级完成。** 如果一个功能需要超过 2 次点击才能到达，重新考虑它的位置。

### 上下文 UI

UI 元素只在用户需要时出现，不需要时消失。

| 触发 | UI | 消失 |
|---|---|---|
| 阅读中点击/轻触 | 顶栏 + 底栏控制层 | 3 秒无操作后淡出 |
| 选中文字 | 高亮气泡（复制/笔记/搜索） | 点击空白处 |
| 滚动浏览书架 | 返回顶部按钮 | 回到顶部后隐藏 |
| 书源异常 | 首页状态卡片提示 | 问题解决后自动消失 |
| 空搜索结果 | 推荐搜索词 + 历史记录 | 输入文字后替换 |

## 5. 主动性 UI

系统应该**主动帮助用户**，而不是被动等待操作。

### 主动行为清单

| 场景 | 系统行为 |
|---|---|
| 打开 App | 显示「继续阅读」，而非空白书架 |
| 无书源 | 自动弹出 onboarding 引导 |
| 书源异常 | 首页静默提示，不阻塞阅读 |
| 长时间未读 | 不催促。书架按最近阅读排序，最近的书自然在最前 |
| 阅读完一章 | 静默保存进度，自动预取下一章 |
| 搜索中 | 逐书源流式返回结果，不等全部完成 |
| 网络断开 | 阅读器继续显示已缓存内容，状态栏低调提示 |

### 禁止的主动行为

- 弹窗催促「你已经 3 天没读了」
- 未经请求的推送通知
- 自动更新书源（用户主动触发）
- 首页推荐算法（除非用户启用 AI 功能）

## 6. 空状态设计

每个空状态都是一个引导机会，不是「无数据」的终点。

### 空状态清单

| 空状态 | 展示内容 | 行动指引 |
|---|---|---|
| 无书源 | App logo + 说明 + 3 种导入方式 | 引导完成首次书源配置 |
| 无书籍 | 书源就绪确认 + 搜索入口 + 书源管理入口 | 让用户知道系统可用，引导搜索 |
| 搜索无结果 | 搜索词 + 建议（换关键词/换书源） | 降低挫败感 |
| 阅读完成 | 章节完成标记 + 「下一章」+ 相关推荐 | 维持阅读流 |
| 书源全部失败 | 温和的错误说明 + 修复指引 | 不恐慌，给出操作路径 |
| 离线无缓存 | 优雅的插画 + 网络恢复提示 | 安静等待 |

### 空状态原则

- 永远不显示空白页面。
- 每个空状态有且仅有一个主要行动按钮。
- 语气友好但不幼稚。
- 视觉上使用微妙的动画（ambient motion）增加生气，但不过分。

## 7. 过渡与动效

Motion 不是装饰。它是空间连续性的载体。

### 过渡原则

| 原则 | 实现 |
|---|---|
| **元素有来源** | 每个新出现的 UI 元素都有明确的「从哪里来」 |
| **状态有连续性** | 书卡 → 详情 → 阅读器是同一个元素的 morph |
| **消失有去处** | 关闭不是消失，而是「回到它来的地方」 |
| **速度有节奏** | 进入快（150ms），退出慢（250ms），阅读区无动效 |

### 关键过渡

| 过渡 | 技术 | 时长 |
|---|---|---|
| 书卡 → 书籍详情 | View Transitions API + shared element | 300ms spring |
| 书籍详情 → 阅读器 | CSS transform scale + fade | 400ms ease-out |
| 阅读器控制层浮出 | opacity + backdrop-filter | 150ms ease |
| 阅读器控制层消失 | opacity fade | 250ms ease + 3s delay |
| Tab 切换 | cross-fade | 150ms |
| 搜索结果到达 | stagger fade-in | 每个 50ms 间隔 |
| ⌘K 命令面板 | scale(0.95→1) + opacity + backdrop | 200ms spring |

### 禁止的动效

- 弹跳动画（bounce）
- 旋转 loading（用 skeleton / shimmer 替代）
- 全局 loading 转圈（用渐进式加载替代）
- 任何超过 500ms 的过渡

## 8. 视觉系统

### Surface 层级（零 border 设计）

全部通过背景明度和透明度区分层级，不用实线边框。

```
Surface 0  基底     侧边栏区域、最底层背景
Surface 1  内容     主内容区
Surface 2  提升     卡片、列表项、hover 状态
Surface 3  悬浮     弹出层、active 状态、强调
Surface 4  模态     对话框、Sheet 背景（加 backdrop-blur）
```

暗色模式 token：

```
Surface 0: oklch(0.13 0.01 260)
Surface 1: oklch(0.16 0.012 260)
Surface 2: oklch(0.19 0.014 260)
Surface 3: oklch(0.22 0.015 260)
```

亮色模式 token：

```
Surface 0: oklch(0.98 0.002 260)
Surface 1: oklch(0.995 0.001 260)
Surface 2: oklch(0.96 0.003 260)
Surface 3: oklch(0.93 0.004 260)
```

### 圆角系统

严格分级，不允许随意取值：

```
4px   微元素（badge、tag 内部）
8px   小组件（按钮、输入框、icon 容器）
12px  卡片（列表项、书卡、chip）
16px  浮层（Sheet、Modal、下拉菜单）
24px  页面容器（主内容区圆角）
```

### 图标策略

减少对 emoji/icon 的依赖。优先使用排版（typography）和间距传达信息。

| 允许 | 禁止 |
|---|---|
| 导航项用小而一致的 Lucide 图标 | 每个列表项都有装饰性图标 |
| 状态用颜色 + 小点指示 | 用大 emoji 表示状态 |
| 操作用文字标签 | 纯图标按钮（必须配文字） |

### 呼吸感

- 卡片间距 ≥ 12px
- Section 间距 ≥ 28px
- 内容区 padding ≥ 24px（桌面）/ 16px（移动）
- 阅读器段落行距 ≥ 1.8em
- 阅读器左右留白 ≥ 40px（桌面）/ 20px（移动）

## 9. 主题系统

### 两层独立

全局 UI 主题和阅读器主题完全独立，互不影响。

**全局 UI 主题**：

| 值 | 说明 | 存储 |
|---|---|---|
| `light` | 亮色 | cookie（SSR 兼容） |
| `dark` | 暗色 | cookie |
| `system` | 跟随系统 | cookie |

实现：next-themes，通过 `.dark` class 切换。

**阅读器主题**：

| 值 | 背景 | 文字 | 色调 |
|---|---|---|---|
| `warm-white` | oklch(0.98 0.005 80) | oklch(0.30 0.01 60) | 暖白 |
| `beige` | oklch(0.93 0.02 80) | oklch(0.28 0.02 60) | 米黄 |
| `green` | oklch(0.92 0.03 155) | oklch(0.25 0.02 140) | 护眼绿 |
| `sepia` | oklch(0.25 0.03 60) | oklch(0.75 0.03 70) | 深褐 |
| `black` | oklch(0.12 0 0) | oklch(0.65 0 0) | 纯黑 |

存储：Zustand + IndexedDB 持久化。只影响阅读器内容区的 3 个 CSS token（`--reader-bg`、`--reader-text`、`--reader-text-secondary`）。

## 10. 多语言（i18n）

### 策略

- **范围**：UI 文字支持中文/英文。书源规则和小说内容不翻译。
- **方案**：next-intl，无 URL 前缀。
- **检测**：cookie → Accept-Language header → 默认 zh。
- **切换**：Server Action 写 cookie + router.refresh()。

### 文件结构

```
apps/web/
  messages/
    zh.json          # 中文翻译
    en.json          # English translations
  i18n/
    request.ts       # 语言检测逻辑
    routing.ts       # next-intl 配置
```

### 使用规范

- Server Component：`const t = await getTranslations()` → `t("home.title")`
- Client Component：`const t = useTranslations()` → `t("home.title")`
- 所有用户可见文字必须通过 `t()` 获取，零硬编码。
- 翻译 key 按功能模块命名：`home.*`、`reader.*`、`sources.*`、`common.*`。

## 11. 导航架构

### 桌面端

- **56px 浮动侧边栏**：无背景、无边框、仅图标。hover 显示 tooltip + 文字。active 状态用左侧 3px 竖线指示。
- **毛玻璃顶栏**：`backdrop-filter: blur(20px)` + 半透明背景。包含页面标题、⌘K 搜索入口、主题切换。
- **⌘K 命令面板**：全局效率入口。搜索书籍、导航页面、管理书源、快捷操作。

侧边栏项：

```
R (logo)     ← 点击回首页
首页         ← 状态恢复中心
书库         ← 全部书籍、分组、管理
发现         ← 书源精选内容
─────────────
搜索         ← ⌘K 更快，这里是备用入口
             ← 弹性空间
书源         ← 书源管理（一级入口）
```

### 移动端

- **4 Tab 底栏**：首页 / 书库 / 发现 / 我的。毛玻璃效果。
- **书源管理**在「我的」中有快捷入口，桌面端在侧边栏有一级入口。
- **搜索**用顶栏常驻搜索框，不是独立 Tab。

### 阅读器导航

阅读器是 Layer 2，全屏沉浸。

- 进入：从书籍详情 morph 过渡。
- 控制层：点击/轻触浮出（顶栏 + 底栏），3 秒无操作淡出。
- 退出：Esc 键 / 返回手势 / 顶栏返回按钮，morph 回上层。
- ⌘K：阅读器内也可唤起命令面板。

## 12. 书源体验设计

书源是 ReaderX 的生命线。没有书源，一切功能无法工作。

### 生命周期

```
首次启动 → 无书源检测 → Onboarding 引导
                        ↓
               导入书源（URL / JSON / 推荐）
                        ↓
               逐个校验 + 实时进度反馈
                        ↓
               首页显示书源就绪状态
                        ↓
日常使用 → 首页卡片显示书源数量和健康状态
                        ↓
         书源异常 → 静默提示，不阻塞
                        ↓
         用户主动检查更新 / 管理书源
```

### 书源在 UI 中的位置

| 位置 | 桌面端 | 移动端 |
|---|---|---|
| 侧边栏/Tab | ⚙️ 一级入口 | 「我的」内快捷入口 |
| 首页 | 状态卡片（N 个书源已就绪） | 同桌面 |
| 顶栏 | 「+ 导入书源」按钮 | 搜索栏旁 |
| ⌘K | "管理书源" "导入书源" 命令 | N/A |
| 首次使用 | 全屏 Onboarding | 全屏 Onboarding |

### 书源管理页面

- 列表式，非网格。
- 每行显示：名称、域名、健康状态标签（正常/异常）、规则覆盖范围、快速操作（调试/编辑）、启用开关。
- 顶部过滤：全部 / 已启用 / 已禁用 / 异常。
- 搜索书源名称。

## 13. 响应式断点

| 断点 | 宽度 | 导航 | 布局 |
|---|---|---|---|
| Mobile | < 768px | 底部 Tab | 单列，横向滚动卡片流 |
| Tablet | 768–1024px | 侧边栏折叠（56px 图标） | 两列自适应 |
| Desktop | > 1024px | 侧边栏浮动（56px） | 多列，⌘K 可用 |

阅读器在所有断点全屏沉浸，无侧边栏。

## 14. 技术栈映射

| 设计决策 | 技术实现 |
|---|---|
| 状态空间导航 | View Transitions API + Next.js parallel routes |
| 毛玻璃效果 | `backdrop-filter: blur()` + oklch alpha |
| Surface 层级 | CSS custom properties，全局/暗色两套 token |
| 过渡动效 | CSS `@starting-style` + `transition` + View Transitions |
| 主题切换 | next-themes（cookie + `.dark` class） |
| 阅读器主题 | Zustand store → CSS class（`.reader-theme-*`） |
| 多语言 | next-intl（无 URL 前缀，cookie 检测） |
| 命令面板 | cmdk（shadcn/ui Command 组件） |
| 组件库 | shadcn/ui + Radix UI + Tailwind CSS v4 |
| 字体 | Inter（UI）+ 系统衬线体（阅读器可选） |
| 色彩空间 | 全局 oklch，零 hex/rgb |

## 15. 验收标准

设计完成度不取决于「画了多少页面」，而取决于以下问题是否都有明确答案：

- [ ] 用户第一次打开 App，30 秒内能开始阅读吗？
- [ ] 用户第二次打开 App，1 次点击能恢复阅读吗？
- [ ] 从看到书卡到进入阅读器，是连续的空间变化还是页面跳转？
- [ ] 阅读器中 UI 完全消失后，用户知道如何唤出控制层吗？
- [ ] 每个空状态都有行动指引吗？
- [ ] 书源异常时用户阅读流被打断了吗？
- [ ] 中英文切换后所有 UI 文字都正确显示吗？
- [ ] 暗色模式下所有层级都清晰可辨吗？
- [ ] 移动端单手能完成 80% 的操作吗？
- [ ] ⌘K 能覆盖 90% 的桌面端操作入口吗？
