# ReaderX PRD — 产品需求文档

> 本文档是所有设计文档的根。下游文档（IA、User Flow、Wireframes、Design Tokens、Component Tree）的决策均源自此处。

## 1. 产品定义

ReaderX 是 [Legado（阅读）](https://github.com/gedoor/legado) 的 Web 重写增强项目。

**定位**：私人阅读工具。管理是手段，阅读是目的。

**性质**：阅读器，不是内容平台。用户知道自己要读什么，核心路径是"我有书 → 我读书"或"搜索 → 找到 → 阅读"。

## 2. 核心价值排序

设计决策冲突时，按此顺序取舍：

```
1. 快   — 瞬时感，操作零延迟
2. 稳   — 认知稳定，可预测，不意外
3. 安静 — UI 退让，内容始终是主角
4. 简单 — 路径短，层级少，概念少
5. 好看 — 精密但不抢戏
```

快排在第一位。不是"快且好看"，是"快，然后在快的基础上好看"。

### 速度哲学

| 场景 | 目标 |
|---|---|
| 点击书籍进入阅读 | < 200ms 可见反馈 |
| 翻页 | 下一帧即显示，无动画延迟 |
| 切换章节 | < 300ms 内容替换 |
| 搜索出结果 | 流式返回，不等全部 |
| 打开设置 | 即时，无加载态 |

动画永远不能阻塞操作。任何 transition 都可以用操作打断。高频使用后动画应自动减弱。

### 认知稳定性

用户第 300 次打开书时，不应该还在"感受设计"。

- 同一个操作，永远在同一个位置触发，永远产生同一个结果
- UI 元素的位置固定，不随上下文变化而移动
- 返回行为可预测：Esc / 返回手势永远回到上一状态，没有例外
- 颜色、字号、间距不因页面而异

**稳定 > 聪明。** 如果一个"智能"行为可能让用户困惑，用"笨但稳定"的方案。

## 3. 目标用户

| 模式 | 特征 | 设计响应 |
|---|---|---|
| 睡前读 | 躺着，单手，低光 | 暗色主题舒适、大点击区域、少蓝光 |
| 通勤读 | 碎片时间，网络不稳 | 离线优先、快速恢复位置、3 秒内进入阅读 |
| 连续阅读 | 长时间沉浸，1-2 小时 | UI 最小化、零打断、自动预取 |
| 跳章浏览 | 快速扫描目录、找特定章节 | 目录随时可达、搜索章节标题 |
| 回忆重读 | 找特定段落、角色、情节 | 全文搜索、书签、阅读历史 |
| 获取新书 | 明确知道要什么，搜索即走 | 搜索快、结果准确、一键加入书架 |

## 4. 明确不做

- **不做社交**。没有关注、动态、评论、分享到社交网络
- **不做社区**。没有书评广场、排行榜、读者圈
- **不做推荐算法**。书架是用户自己的，不是算法投喂的
- **不做 gamification**。没有阅读时长、连续打卡、成就徽章
- **不做内容平台**。用户知道自己要读什么，"发现"是书源能力的展示，不是内容推送

## 5. 功能范围

### P0 — MVP（最小可用产品）

| 功能 | 说明 | Web 端实现 |
|---|---|---|
| **阅读器** | 滚动模式、分页模式、点击/键盘/触摸翻页、阅读进度、自动预加载、章节切换、阅读历史、字号·行距·主题可调、选中文字浮出菜单 | reader-engine + DOM 渲染 + RenderScheduler |
| **书架** | 网格/列表视图、分组管理、长按操作、排序（最近阅读/添加时间/书名/手动拖拽）、下拉刷新 | IndexedDB + TanStack Query |
| **搜索** | 多书源并发搜索、搜索历史、流式结果、书源选择（全部/分组/指定） | Worker Bridge 并发 |
| **书源管理** | Scraping Workspace（导入/编辑/调试/校验） | 已完成核心 |
| **目录** | 章节列表、搜索跳转、章节搜索 | 阅读器内面板 |
| **进度恢复** | 精确位置保存、再次打开恢复、章节预取 | IndexedDB |
| **书签** | 添加/管理/跳转 | IndexedDB |
| **主题** | 亮/暗/系统 + 5 套阅读器主题 | CSS custom properties |
| **换源** | 同名搜索换源、多书源结果去重、保持阅读进度 | 多书源结果合并 |
| **离线缓存** | 自动缓存最近章节、当前书籍缓存、阅读预加载 | OPFS + Service Worker |
| **Legado 迁移** | 导入 books.json / bookSource.json / replaceRule.json / rssSource.json | File API + Zod 校验 |
| **多语言** | UI 文案支持中文/英文（书源规则和小说内容不翻译），next-intl，无 URL 前缀，cookie 检测 | next-intl + Server Action |

## 6. 非功能需求（NFR）

ReaderX 真正能超越 Legado 的地方，不是功能数量，而是底层体验指标。

| 指标 | 目标 | 衡量方式 |
|---|---|---|
| **启动速度** | 首屏 < 1s / 恢复阅读位置 < 200ms | Lighthouse Performance |
| **搜索速度** | 首条结果 < 2s / 流式返回不等全部 | 首条结果到达时间 |
| **离线能力** | Service Worker / 缓存优先 / 离线可阅读已缓存内容 | 断网测试 |
| **数据安全** | 本地加密存储 / 规则沙箱隔离 / 无外部数据泄露 | 安全审计 |
| **规则兼容率** | 与 Legado 书源格式 > 90% 兼容 | 兼容性测试矩阵 |
| **跨平台一致** | PWA / 桌面(Electron/Tauri) / 移动端体验一致 | 多端对比测试 |

## 8. 设计文档使用说明

下游设计文档（IA、User Flow、Wireframes、Design Tokens、Component Tree）描述了 ReaderX 的**完整目标态**，包含所有 P0-P3 功能。

**实施时应以本 PRD 的优先级分层为准**：
- P0 功能的完整设计 → MVP 必须实现
- P1-P2 功能的设计 → 提前规划，按优先级实施
- P3/Future → 仅作架构预留

这意味着：
- IA、Wireframes、Component Tree 中包含了发现页（P2）和 RSS 订阅（P1）的完整设计，但 MVP 不需要实现
- MVP 实施时，导航只显示 P0 相关的 Tab（书架 + 我的），发现和订阅 Tab 在对应功能实施后通过智能显隐出现
- 所有设计文档的结构保持完整，避免后续补充时遗漏

## 9. 验收标准

- [ ] 第一次打开 App，30 秒内能开始阅读？
- [ ] 第二次打开 App，1 次点击能恢复阅读？
- [ ] 搜索到结果到进入阅读器，< 2 次点击？
- [ ] 阅读器中 UI 消失后，用户知道怎么唤出？
- [ ] 书源异常时阅读流被打断了吗？
- [ ] 单章失败时，其他章节正常？
- [ ] 中英文切换后所有文字正确？
- [ ] 暗色模式所有层级清晰？
- [ ] 移动端单手完成 80% 操作？
- [ ] 从点击到看到内容，体感是"瞬间"还是"在等"？
- [ ] 断网时能继续阅读已缓存内容？
- [ ] Legado 数据导入后书架立即可用？
