# ReaderX User Flow — 用户流程

> 本文档定义核心用户操作流程和故障降级路径。页面结构见 [IA](./ia.md)，功能范围见 [PRD](./prd.md)。

## 1. 核心流程

### 1.1 首次启动（Legado 迁移）

```
打开 ReaderX
  → 空书架 + 引导卡片
  → 用户选择：
     A. 导入 Legado 数据（推荐）
        → 选择文件（支持多文件：bookSource.json + books.json + replaceRule.json + rssSource.json）
        → Zod 校验 + 兼容性分析
        → 导入结果报告（成功 N / 警告 M / 失败 K）
        → 书源就绪 → 书架显示已导入书籍
     B. 手动添加书源
        → URL / 文件 / 粘贴导入
        → 校验 → 书源就绪
     C. 跳过，直接搜索
        → 进入搜索页 → 搜索 → 加入书架
```

### 1.2 日常阅读（最核心流程）

```
书架（首页）
  → 看到"继续阅读"Hero 卡片
  → 点击封面
  → 阅读器（全屏，fade in 150ms）
     → 自动恢复到上次阅读位置
     → 翻页阅读（触摸滑动 / 键盘方向键 / 点击屏幕区域）
     → 当前章节读完 → 自动加载下一章（章节末尾有"下一章"按钮）
     → 点击屏幕中心 → 控制层浮出
       → 顶栏：返回按钮 + 章节标题 + 菜单（换源/书签/设置）
       → 底栏：上一章 + 进度百分比 + 下一章
       → 3 秒无操作 → 控制层淡出
     → 点击菜单 → 设置面板（字号/行距/主题/翻页模式）
     → 点击菜单 → 目录面板（章节列表 + 搜索）
     → Esc / 返回手势 / 顶栏返回 → 退出阅读器（fade out 150ms）
  → 回到书架（记住滚动位置）
```

### 1.3 搜索添加书籍

```
书架 Toolbar → 点击搜索图标
  → 搜索页（全屏）
  → 输入关键词（debounce 300ms）
  → 多书源并发搜索
  → 流式展示结果（stagger fade-in，每个 30ms）
  → 点击搜索结果
  → 书籍详情页
     → 查看封面/简介/作者/最新章节
     → 操作：
        - 加入书架 → 回到书架，新书出现在列表中
        - 立即阅读 → 进入阅读器
        - 换源 → 查看其他书源的同名书
```

### 1.4 换源（核心能力）

```
触发点：
  A. 阅读中 → 控制层 → 换源
  B. 书籍详情页 → 换源
  C. 章节加载失败 → 提示换源

流程：
  → 用书名搜索所有书源
  → 列出可用书源（标记当前源、成功/失败/慢）
  → 选择新源
  → 内容切换（保持阅读位置：章节标题 + 进度百分比）
  → 阅读继续
```

### 1.5 发现浏览

```
发现 Tab → 书源列表（按分组过滤）
  → 点击书源标题行 → 展开分类标签（FlexboxLayout）
     玄幻 | 都市 | 完本 | 热门 | ...
  → 点击分类标签 → 分类书籍列表（自动翻页）
  → 点击书籍 → 书籍详情
```

### 1.6 订阅阅读

```
订阅 Tab → RSS 源列表
  → 查看新文章数角标
  → 点击源 → 文章列表（分类选择）
  → 点击文章 → 文章阅读
  → 收藏文章 → 订阅收藏页
```

### 1.7 书源管理

```
我的 → 书源管理
  → Scraping Workspace
  → 列表（Layer 0）：搜索/筛选/启用开关/能力标记
  → 编辑（Layer 1）：可折叠规则组 + Schema-aware 编辑器
  → 调试（Layer 2）：Pipeline Timeline + Network Inspector + Console
  → 导入/导出/校验
```

## 2. 交互操作层级

| 层级 | 触发 | 示例 | 目标覆盖率 |
|---|---|---|---|
| **零操作** | 系统主动 | 继续阅读 Hero | — |
| **单操作** | 一次点击 | 点击封面进入阅读、切换 Tab | 80% |
| **上下文操作** | 在内容上操作 | 选中文字 → 浮出菜单 | 15% |
| **深层操作** | 设置/管理 | 书源管理、备份恢复 | 5% |

超过 2 次点击到达的功能，考虑移位置。

## 3. 上下文 UI

UI 在需要时出现，不需要时消失。出现的位置和方式必须稳定可预测。

| 触发 | UI | 消失 |
|---|---|---|
| 阅读中点击屏幕 | 顶栏 + 底栏 | 3 秒无操作淡出 |
| 选中文字 | 操作菜单（复制/高亮/搜索） | 点击空白 |
| 搜索输入 | 实时结果 | — |

上下文 UI 不移动已有元素。浮层用 overlay，不用 reflow。

## 4. 返回行为

所有返回遵循同一规则：**Esc / 返回手势 = 关闭当前浮层或回到上一页**。

不允许出现：
- "按 Esc 后不知道回到了哪里"
- "返回后之前的滚动位置丢了"
- "返回后需要重新加载"

## 5. 阅读节奏系统

系统根据用户行为模式微调 UI 行为（用户不应感知到"系统在适应我"）：

```
连续阅读 > 20 分钟：
  → 控制层自动隐藏间隔延长（3s → 5s）
  → 动画减弱

快速跳转模式（1 分钟内切换 > 3 章）：
  → 导航元素更持久显示
  → 目录入口更显眼

长时间未读（> 7 天）：
  → 不催促，不通知
  → 书架按最近阅读自然排序
```

## 6. 故障降级路径

### 书源故障

| 故障 | 用户看到什么 | 系统做什么 |
|---|---|---|
| 单章获取失败 | 该章位置显示"加载失败" + 重试按钮 + 跳过按钮 | 自动 retry 1 次，失败后记录，不影响其他章节 |
| 书源超时 | 搜索结果中该书源标记为慢，其他结果正常显示 | 超时 10s 后标记，后台继续等待 |
| 书源完全失败 | 搜索结果底部"N 个书源无响应" | 不弹 toast，不阻塞 |
| 编码乱码 | 显示原文 + "内容异常"提示 | 尝试备选编码自动修复 |
| 目录成功但正文失败 | 目录正常显示，失败章节灰色 + 重试 | 静默 retry，不丢失阅读位置 |
| 网络断开 | 阅读器继续显示已缓存内容，顶栏低调提示 | 缓存优先 |
| 所有书源失败 | 温和说明 + 修复指引 + 换源按钮 | 每个书源显示具体错误 |

### 故障原则

- **永远不弹 modal 阻塞阅读**。错误信息用 inline 提示
- **部分失败不影响整体**。10 个书源 3 个失败，显示 7 个的结果
- **保留用户状态**。失败后重试不丢失阅读位置、搜索词、滚动位置
- **给出操作路径**。每个错误都有明确的"下一步"
- **不恐慌**。错误提示语气平和，不使用感叹号、红色警告色

## 7. 空状态设计

每个空状态是引导机会，不是"无数据"终点。

| 空状态 | 展示 | 主要行动按钮 |
|---|---|---|
| 无书源 | Logo + 说明 + 3 种导入方式 | 导入书源 |
| 无书籍 | 书源就绪提示 + 搜索入口 | 搜索书籍 |
| 搜索无结果 | 搜索词 + 建议 | 调整关键词 |
| 阅读完成 | 章节完成 + 下一章按钮 | 继续阅读 |
| 书源全部失败 | 温和说明 + 修复指引 | 换源 |
| 离线无缓存 | 插画 + 网络恢复提示 | 等待 |
| 无发现分类 | 无 exploreUrl 书源提示 | 管理书源 |
| 无 RSS 源 | 订阅源导入引导 | 导入订阅源 |

原则：
- 永远不显示空白页
- 每个空状态有且仅有一个主要行动按钮
- 语气友好但不幼稚
- 不使用动画（零 ambient motion）
