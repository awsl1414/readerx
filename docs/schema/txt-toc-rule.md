# ReaderX TXT 目录规则 v1

> Web-first，不兼容 Legado

TXT 目录规则用于从纯文本文件中识别章节标题行。当用户导入本地 TXT 文件时，引擎按 `order` 顺序尝试每条规则，匹配到的行即为章节分界点。

## 与书源 toc 规则的区别

| | 书源 toc | TXT 目录规则 |
|---|---|---|
| 数据来源 | HTML/JSON 网络响应 | 本地纯文本文件每一行 |
| 匹配方式 | CSS/XPath/JSONPath 提取 | 行级正则匹配 |
| 用途 | 在线阅读时提取目录 | 离线 TXT 导入时识别章节 |

## 字段一览

| 字段 | 类型 | 必须 | 默认值 | 说明 |
|---|---|---|---|---|
| `name` | string | ✅ | — | 规则名称，用于 UI 展示 |
| `description` | string | — | `""` | 示例文本，说明此规则匹配什么样的章节标题 |
| `tags` | string[] | — | `[]` | 分组标签，用于 UI 筛选 |
| `enabled` | boolean | — | `true` | 是否启用 |
| `order` | integer | — | `0` | 执行顺序，越小越先匹配 |
| `pattern` | string | ✅ | — | 正则表达式。空字符串 = 兜底规则 |
| `flags` | string | — | `"gm"` | 正则标志 |

### flags 常用值

| 值 | 含义 | 适用场景 |
|---|---|---|
| `"gm"` | 全局 + 多行 | 默认，`^$` 匹配行首行尾 |
| `"gmi"` | 全局 + 多行 + 忽略大小写 | 英文标题（Chapter/Section） |
| `"g"` | 仅全局 | 单行文本匹配 |

### 匹配机制

引擎对 TXT 文件的**每一行**执行 `pattern` 匹配。匹配成功的行被识别为章节标题，并以此分章。

`order` 决定匹配优先级——通常由具体（如「第 X 章」）到通用（如纯数字）排列。

## 标签约定

| 标签 | 含义 |
|---|---|
| `标准` | 最常见的中文章节格式 |
| `数字` | 数字编号章节 |
| `英文` | 英文 Chapter/Section 格式 |
| `符号` | 特殊符号开头的标题 |
| `书名` | 书名+序号格式 |
| `可选` | 默认关闭，可能误匹配 |
| `激进` | 非常宽泛的匹配规则 |
| `兜底` | 最后的 fallback 规则 |

## 与其他规则的关系

- **书源 toc 模块**：从在线 HTML/JSON 响应中提取目录——结构化数据提取
- **TXT 目录规则**：从本地纯文本中匹配章节标题行——行级正则匹配
- **净化规则**：对已提取的正文做文本替换——不影响章节识别
